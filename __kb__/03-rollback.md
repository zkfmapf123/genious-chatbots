# 롤백 절차

> 샘플 문서: 챗봇 RAG 테스트용으로 만든 가상의 사내 절차다.

## 언제 롤백하나

- 카나리 단계에서 에러율이나 지연이 기준을 넘었을 때
- 배포 직후 결제 실패, 로그인 실패처럼 핵심 기능이 깨졌을 때
- 원인을 10분 안에 못 찾을 때: **원인 분석보다 복구를 먼저 한다.**

## 방법 1: 이전 버전으로 되돌리기 (기본)

```bash
kubectl rollout undo deployment/payment-api
kubectl rollout status deployment/payment-api
```

직전 리비전으로 돌아간다. 특정 리비전으로 가려면 `--to-revision=N`을 쓴다. 리비전 목록은 `kubectl rollout history deployment/payment-api`로 본다.

## 방법 2: 이미지 태그 고정 재배포

배포 도구에서 **이전에 성공한 커밋 SHA**를 골라 다시 배포한다. 롤아웃 기록이 지워졌거나 여러 버전 전으로 가야 할 때 쓴다.

## 롤백이 안 되는 경우

- **DB 마이그레이션이 이미 적용됐다**: 코드만 되돌리면 스키마가 안 맞을 수 있다. 마이그레이션이 이전 버전과 호환되게 만들어졌는지 확인하고, 안 된다면 DB 담당자와 함께 판단한다. 임의로 마이그레이션을 되돌리지 않는다.
- **피처 플래그로 막을 수 있다**: 새 기능이 플래그 뒤에 있으면 배포를 되돌리지 말고 플래그를 끈다.

## 롤백 후

1. 채널에 롤백 사실과 이유를 공유한다.
2. 장애 기록에 시각, 증상, 롤백한 버전을 적는다.
3. 원인 분석은 서비스를 복구한 뒤 한다.
