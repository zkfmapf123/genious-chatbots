# CI 파이프라인

> 샘플 문서: 챗봇 RAG 테스트용으로 만든 가상의 사내 절차다. 실제 팀 규칙이 아니다.

## 개요

PR이 열리면 CI가 자동으로 돈다. 모든 단계가 통과해야 머지할 수 있다.

## 단계

1. **체크아웃**: PR 브랜치를 받는다.
2. **의존성 설치**: 락 파일(`package-lock.json`)을 기준으로 설치한다. 캐시 키는 락 파일 해시다.
3. **린트·타입 검사**: `npm run lint`, `tsc --noEmit`. 실패하면 이후 단계를 건너뛴다.
4. **단위 테스트**: `npm test`. 커버리지는 참고용이고 머지 조건은 아니다.
5. **빌드**: `npm run build`로 산출물을 만든다.
6. **이미지 빌드·푸시**: 커밋 SHA를 태그로 컨테이너 이미지를 만들어 레지스트리에 올린다. `latest` 태그는 배포에 쓰지 않는다.
7. **취약점 스캔**: 이미지 스캔에서 high 이상이 나오면 실패한다.

## 자주 나는 실패

- **캐시가 오래돼 설치가 실패한다**: 락 파일이 바뀌었는데 캐시가 남아 있는 경우다. CI에서 캐시를 지우고 다시 돌린다.
- **린트만 실패한다**: 로컬에서 같은 명령을 돌려 보고 고친 뒤 푸시한다.
- **이미지 푸시 권한 오류**: 레지스트리 자격증명 시크릿이 만료된 경우가 많다. 플랫폼 팀에 갱신을 요청한다.
