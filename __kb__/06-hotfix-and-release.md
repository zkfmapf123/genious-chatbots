# 핫픽스와 릴리스 규칙

> 샘플 문서: 챗봇 RAG 테스트용으로 만든 가상의 사내 절차다.

## 일반 릴리스

- main에 머지된 변경은 일주일에 두 번(화·목) 묶어서 배포한다.
- 릴리스 노트에는 변경 요약, 마이그레이션 여부, 롤백 시 주의점을 적는다.
- 배포 담당자는 돌아가며 맡고, 담당자가 배포 공지와 모니터링까지 책임진다.

## 핫픽스

운영 장애나 보안 이슈처럼 다음 정기 배포를 기다릴 수 없을 때만 쓴다.

1. 최신 main에서 `hotfix/<이슈>` 브랜치를 만든다.
2. 변경은 **문제를 고치는 최소한**으로 한다. 겸사겸사 하는 리팩터링은 넣지 않는다.
3. 리뷰어 1명 이상의 승인을 받는다 (긴급 시 채널에서 구두 승인 후 사후 리뷰).
4. 일반 배포와 같은 카나리 절차를 따른다. 단계 간격은 줄여도 되지만 생략하지 않는다.
5. 배포 후 main에도 같은 수정이 들어갔는지 확인한다.

## 배포 동결(freeze)

- 연말 연시, 대규모 이벤트 기간에는 배포를 동결한다.
- 동결 기간에는 핫픽스만 허용하고 담당 리더의 승인이 필요하다.

## 배포 기록

모든 배포는 버전(커밋 SHA), 시각, 담당자, 결과(성공·롤백)를 기록한다. 장애가 났을 때 "직전에 무엇이 배포됐나"를 가장 먼저 확인하기 위해서다.
