# 배포 절차 (payment-api 기준)

> 샘플 문서: 챗봇 RAG 테스트용으로 만든 가상의 사내 절차다. 서비스 이름과 시간은 예시다.

## 배포 전 확인

- main 브랜치의 CI가 모두 초록색인지 본다.
- 배포할 커밋 SHA와 이미지 태그가 같은지 확인한다.
- DB 마이그레이션이 있으면 **이전 버전과 호환되는지** 먼저 본다 (컬럼 삭제·이름 변경은 두 번에 나눠 배포한다).
- 금요일 오후와 공휴일 전날에는 긴급 수정이 아니면 배포하지 않는다.

## 배포 순서

1. 배포 채널에 "payment-api 배포 시작, 커밋 SHA"를 공지한다.
2. 스테이징에 먼저 배포하고 스모크 테스트(`/health`, 결제 조회 API)를 확인한다.
3. 프로덕션에 **카나리 10%**로 배포한다.
4. 10분간 에러율과 지연 시간을 본다. 기준은 아래 "카나리 판단 기준"이다.
5. 문제가 없으면 50%, 100% 순서로 올린다. 단계마다 5분 이상 간격을 둔다.
6. 완료를 채널에 알리고 배포 기록(버전, 시간, 담당자)을 남긴다.

## 카나리 판단 기준

| 지표 | 계속 진행 | 중단하고 롤백 |
|---|---|---|
| 5xx 에러율 | 기존 대비 +0.5%p 이내 | +1%p 초과 |
| p95 지연 시간 | 기존 대비 +20% 이내 | +50% 초과 |
| 재시작 횟수 | 0회 | 파드 재시작 반복 |

기준 사이 값이면 5분 더 관찰하고 판단한다.

## 배포 후

- 30분간 대시보드를 본다.
- 이상이 있으면 즉시 `03-rollback.md`의 롤백 절차를 따른다.
